# M1 复读机 App 录屏脚本

> 用途：给上级做进度汇报录屏时，照这份脚本一步步操作即可出画面。
> 结论先行：工程是**真实可编译、可打包**的 Flutter App，核心 6 个 M1 功能都有真实实现（非空壳）。
> 本机（撰写本脚本时）**没有连接真机、也没装模拟器**，因此本次无法代跑真机画面；下面给你的是「自己照着敲就能出画面」的完整命令。

## 0. 工程现状一句话结论

`D:\AI-sound-card\app` 是一个用 Flutter 3.47.4 + Riverpod + go_router + just_audio + record + sqflite 实现的「录音卡」英语口语练习 App。M1 复读机引擎的六个功能（变速、断句、AB 循环、跟读对比、波形显示、按住说话）**代码齐全且是真逻辑**，`flutter pub get` / `flutter analyze` / `flutter build apk --debug` 均通过，能打出可安装的 debug APK。唯一遗憾是本机无真机/模拟器，录音链路必须真机才能实跑。

## 1. 前置准备（一次做好）

1. **必须用 Android 真机**（不能用模拟器）：本项目是录音 App，模拟器没有真实麦克风输入，`record` 插件的录音链路测不了。
2. 手机开「开发者选项 → USB 调试」，用 USB 线连电脑，手机上弹「允许 USB 调试」要点允许。
3. 手机**系统时间/时区设对**，否则录音文件时间戳会错。
4. 环境已就绪（无需重装）：Flutter 3.47.4 + Android SDK 36 + JDK 21，见 `docs/环境搭建说明.md`。
5. 首次录音时 App 会弹**麦克风权限**，点允许。

## 3. 启动 App 并录制演示（建议顺序）

> 录屏建议用 `scrcpy` 或手机自带录屏；分辨率调竖屏。每段动作控制节奏，语速功能靠「听」体现，建议录音时把手机外放/耳机都准备好。

### 3.1 启动

```powershell
flutter run
```

**应该看到**：Gradle 首次构建约 1–3 分钟，之后 App 自动装到手机并打开，终端进入热重载交互模式（按 `r` 热重载、`q` 退出）。
**演示动作（约 5 秒）**：先拍一眼终端出现 `Launching ... / Syncing files`，然后镜头切到手机屏幕——首页出现「示例句子 People」卡片和「录音列表 / 复习池」两个入口。

### 3.2 首页（约 5 秒）

- 画面：标题「录音卡」，一张句子卡片「People / ˈpiːp(ə)l / 人们；人民 · 时长 00:05.3」，下面两个入口卡片「录音列表」「复习池」。
- 讲解词：这是本地种子数据，首次启动自动写入示例句子并把示例原声复制到应用目录，不依赖后端。

### 3.3 复读机练习页（核心，约 40 秒）

点「People」卡片右侧的**耳机图标**（复读机练习）进入练习页。

进入后从上到下依次演示：

**a. 波形显示（约 5 秒）**
- 画面：顶部句子卡片，下面一张卡片里画着蓝绿色上下镜像波形。
- 这是从 PCM 音频分 800 桶抽取峰值实时绘制的真实波形，不是静态假图。

**b. 播放 / 进度（约 8 秒）**
- 点中间的播放圆形按钮。
- **应该看到**：波形已播放部分高亮变色，进度条前进，左侧时间从 00:00.0 递增到 00:05.3，按钮变成暂停图标。点暂停能停住。

**c. 变速（约 10 秒，重点靠听）**
- 点「语速」下面的档位：先点 `1.5x` 再点 `0.5x`，各播几秒。
- **应该看到/听到**：播放速度明显变快/变慢，但**音调不变**（男声还是男声），这是 ExoPlayer + Sonic 变速不变调。档位选中态高亮。

**d. AB 复读（约 12 秒）**
- 先点「设置 A」（在播放到某个位置时点，取当前位置为 A 点），继续播几秒再点「设置 B」。
- **应该看到**：两个按钮文字变成 `A 00:0X.X` / `B 00:0X.X`。
- 再点「重复次数」里的 `2`，点播放，让它越过 B 点。
- **应该听到**：声音在 A→B 之间来回循环，共 3 次后停止。「循环间隔」用加减号可调 0.5s 步进。
- 演示完点「清除 AB」（右上角 X 图标）。

**e. 断句（约 5 秒，说明性）**
- 画面底部「断句」列表。种子句是单个词 "People"，所以只会切出 **1 个句段**（形如 `00:00.0 - 00:05.3`），点它的播放箭头会跳过去播这句。
- 讲解词：断句用的是能量阈值静音检测（分帧 RMS + 连续静音切分），真实算法；要演示多句段需录一句带停顿的长句（见第 5 节）。

**f. 按住说话（约 10 秒，重点）**
- 屏幕底部有一条橙色长条按钮「按住说话」。
- **按住不放**，对着手机说一句 "People"。
- **应该看到**：按钮文字变成 `00:0X.X · 松开结束`，颜色略微变深，说明正在录音。
- **上滑超过按钮边界**：按钮变红、文字变「松开取消」，松开即丢弃，不保存。
- 再来一次按住说 ≥1 秒后**直接松开**：底部弹出 SnackBar「录音已保存」。
- 如果只按了不到 1 秒就松：弹「录音太短，已丢弃」（这是产品逻辑，<1s 丢弃）。

**g. 普通录音按钮（约 5 秒，可选）**
- 「按住说话」右边有个麦克风「录音」按钮：tap 开始（变红「停止」）→ 再说一句 → tap 停止保存。与按住说话共用同一录音器。

### 3.4 跟读对比页（约 30 秒）

返回首页，点「People」卡片右侧的**双箭头图标**（跟读对比）进入。

**a. 自动播原声（约 5 秒）**
- 画面显示「正在播放原声…」+ 句子文本，自动播放完原声后进入「请跟读」。

**b. 按住跟读（约 8 秒）**
- 按住底部「按住跟读」按钮，跟着读 "People"，松开。

**c. 波形重叠对比（约 8 秒）**
- **应该看到**：出现蓝（原声）+ 橙（我的录音，半透明叠加）两条波形重叠，下方有图例「原声 / 我的录音」。
- 点「播放原声」「播放我的」分别听两条音轨对比。

**d. 三维自评（约 6 秒）**
- 点「三维自评」弹层，拖动「流利度/准确度/完整度」三个滑块（1–5 分），可选填备注，点「保存评估」。
- **应该看到**：SnackBar「评估已保存」。

**e. 标错加入复习池（约 5 秒）**
- 点「标错 · 加入复习池」，弹「已加入复习池」。

### 3.5 录音列表页（约 8 秒）

首页点「录音列表」入口。
- **应该看到**：列出刚才录的几条录音，每条显示时长、来源（练习/跟读）、时间，若做过自评还显示「自评 流X/准X/完X」。点播放箭头可直接回放。

### 3.6 复习池页（约 8 秒）

首页点「复习池」入口。
- **应该看到**：刚才「标错」的那句出现在列表里，带「标错」标签。
- 点「会了」或「又错了」会更新复习调度（下次复习时间、重复次数），点删除图标可移除。

## 5. 已知限制与诚实标注

1. **无法在本会话真机演示**：撰写时 `adb devices` 列表为空（无真机），且 SDK 里没有 `emulator.exe`、没有 AVD（无模拟器）。所以「真机画面」这一步由用户自行跑通，脚本已给出完整命令。
2. **基频 F0 是占位，不是本版演示内容**：`engine/analysis/f0_extractor.dart` 的 `PlaceholderF0Extractor` 只返回空表，真实音高算法（YIN/自相关）标注为 M5 实现。数据库 `recording` 表虽有 `f0_json` 字段，但本版不会写入真实 F0。这不影响 M1 六个功能演示。
3. **断句演示偏弱**：内置种子只有一个单词 "People"（约 5.3 秒），静音检测只会切出 1 个句段。要演示「多句段切分」，需用「按住说话」录一句带明显停顿的长句（如念 "Good morning. Nice to meet you."），再进练习页看断句列表。断句算法本身是真实的（`sentence_segmenter.dart`，纯 Dart RMS 静音检测，有 7 个单测覆盖）。
4. **AB 循环有 3 个单测失败**：`flutter test` 里 `ab_loop_controller_test.dart` 的 3 例报 `Bad state: Cannot fire new event`。根因已定位：测试替身 `_FakePlayer.seek` 用了 `sync:true` 的广播流，`seek` 同步重入 `_onPosition` 触发 Dart 的重入保护；真实 just_audio 的位置流是异步的，不会同步重入，**生产运行不受影响**。建议后续把 `AbLoopController._onPosition` 里的 `_loopOnce()` 改为 `Future.microtask(_loopOnce)` 并同步调整测试断言，可消除隐患。
5. **变速不变调仅保证 Android**：`audio_player_controller.dart` 注释明确 Android 走 ExoPlayer/Sonic 不变调，iOS 的 `AVPlayer.rate` 会变调，M1 只保证 Android 可编译运行。
6. **全程本地、不依赖后端**：数据用 sqflite 存本地（4 张表），录音存应用文档目录。`server/` 与本次演示无关，不需要先起后端。
7. **首次构建慢**：首次 `flutter run` / `flutter pub get` 走国内镜像，可能较慢（pub get 首拉实测可达 20+ 分钟），属带宽问题。

## 6. 用户录制时最容易翻车的 3 个点

1. **adb 认不到手机**：`flutter devices` / `adb devices` 列表为空或显示 `unauthorized`。解法：确认 USB 调试已开、手机上点了「允许」、换数据线（有些线只能充电）、或 `adb kill-server && adb start-server` 重启 adb；必要时装手机厂商 USB 驱动。
2. **把首次慢当成卡死**：首次 `pub get` 和首次 `flutter run` 构建会明显慢（镜像带宽 + Gradle 首次下载），只要终端在持续刷日志、或 `%LOCALAPPDATA%\Pub\Cache\hosted\pub.flutter-io.cn` 里包数量在涨，就是没卡死，耐心等。
3. **录音无声音 / 无权限**：忘记点「允许麦克风权限」，或用了模拟器（无麦克风）。务必真机 + 首次录音时允许权限；另外把手机时间/时区设对，否则录音时间戳错乱。
